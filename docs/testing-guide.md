# Testing guide

Backend tests use pytest + isolated in-memory SQLite databases and FastAPI TestClient. Run from `backend/`: `.venv/bin/pytest -q`. Auth tests cover registration, Argon2id/legacy rehash, verification/reset expiry and replay, sessions/refresh rotation/revocation, authorization, origin checks, throttling and production config. Commerce/payment tests cover API discovery/search/filter/detail, cart CRUD/ownership, fixed-precision DB-price totals, idempotent checkout, address validation, inventory/oversell/cancel restoration, referral cookie attribution, demo success/failure/duplicate attempts, COD unpaid fulfillment/admin collection/duplicate denial, online-payment rejection, admin order filtering and cross-user/access control.

Frontend: `cd frontend && npm run lint && npm test && npx tsc -b && npm run build`. React Testing Library component tests cover search/query behavior, empty/error states, details/quantity/add, cart update/remove, checkout form submission/idempotency key, order history/detail/cancellation. These are component/API-mock tests, not an end-to-end full-stack browser journey; there is no Playwright suite yet.

Run `.venv/bin/alembic upgrade head` against fresh SQLite, a copy of a pre-commerce `0002` database, and verify `.venv/bin/alembic downgrade 0003_customer_commerce`/upgrade against disposable copies. Fresh SQLite upgrade and `0004_payment_options` downgrade/re-upgrade passed locally; PostgreSQL migration/rollback and multi-process concurrency stress remain unverified. Deployment verification must additionally cover Redis, SMTP, trusted proxy/origin, PostgreSQL concurrency, manual COD collection/audit review, and any future provider integration. No real payment provider flows exist; COD collection is an offline admin attestation, and DEMO is simulated.

Before release, run the migration against a disposable SQLite database and a reviewed copy/backup of existing data. Deployment verification must additionally cover PostgreSQL migration rollback, Redis-backed distributed rate limits, SMTP TLS/mail sink, trusted-proxy/origin behavior, concurrency, SQL query scope, and manual COD collection/audit controls. No real payment provider is integrated or testable.
