# Testing guide

Backend tests use pytest + isolated in-memory SQLite databases and FastAPI TestClient. Run from `backend/`: `.venv/bin/pytest -q`. Auth tests cover registration, Argon2id/legacy rehash, verification/reset expiry and replay, sessions/refresh rotation/revocation, authorization, origin checks, throttling and production config. Commerce tests cover API discovery/search/filter/detail, cart CRUD and ownership, DB-price total recomputation, idempotent multi-item checkout, address validation, stale inventory/oversell guard, order snapshots/history/ownership/cancellation/stock restore, status transitions and referral cookie attribution.

Frontend: `cd frontend && npm run lint && npm test && npx tsc -b && npm run build`. React Testing Library component tests cover search/query behavior, empty/error states, details/quantity/add, cart update/remove, checkout form submission/idempotency key, order history/detail/cancellation. These are component/API-mock tests, not an end-to-end full-stack browser journey; there is no Playwright suite yet.

Run `.venv/bin/alembic upgrade head` against fresh SQLite, a copy of a pre-commerce `0002` database, and verify `.venv/bin/alembic downgrade 0002_auth_security`/upgrade against disposable copies. SQLite upgrade/rollback paths passed locally; PostgreSQL migration/rollback and multi-process concurrency stress remain unverified. Deployment verification must additionally cover Redis, SMTP, trusted proxy/origin, payment, refunds and payouts. No payment provider flows exist and no payment can be collected.

Run `alembic upgrade head` against a disposable SQLite DB and against a copy/backup of an existing DB before release. Deployment verification must additionally cover Postgres migration rollback, Redis-backed distributed rate limits, SMTP TLS/mail sink, trusted-proxy/origin behavior, concurrency, SQL query scope, payments and payout flows. The payment provider flows do not exist and are not testable as live payments.
